# Review of the two Muse sessions (2026-09-24)

Read this before quoting anything in `muse_report/` or `scope/`.

## Fixed in the commit that landed with this note

1. **Every Buddy turn re-sent the full briefing.** `runtime.ts` set
   `refreshBuddyContext = !!turnBuddyContext && !!readCurrentBuddyContext`
   (5c0cec4, 2026-09-20), so it was true on every turn in production and
   `buildFirstTurnCliContent` prepended the whole ~18–20k-char briefing each time.
   Evidence: `~/.claude/projects/-Users-nicholasbardy-git-basketball-model/94d99e8d-….jsonl`
   has 44 user turns carrying the briefing (835,592 chars total) across 1,081
   provider requests, and the other recent Buddy sessions show the same pattern
   (`grep -c 'unleashd:buddy-context-v2 '`). Each copy stays in the transcript,
   so every later step re-reads all of them. Now the briefing is re-sent only when
   the provider session's memory generation is new or unknown. Guard:
   `conversation-runtime.test.ts` "re-brief only when the memory generation changes".
2. **The suffix budget was a runtime throw on developer-written prose.** Muse
   raised 2,600 → 3,000, which leaves 325 chars of headroom (owner-thread
   suffix measures 2,675). The next feature line would have caused the same outage.
   The budget is now a test over every audience/automation variant
   (`buddies-integration.test.ts`), and the runtime no longer throws.

## Muse claims that are wrong

- **"Steady-state turns never resend the briefing; memory can't bust cache"**
  (05, 06). False because of bug 1. Muse read the injection function but not
  the flag passed into it.
- **"Codex exec ≈ no auto-compaction"** (06, scope/compaction-economics).
  False: 39 `codex_exec` rollouts from Sep 20–24 contain `compacted` events.
  Claude `-p` compacts too (2 `compact_boundary` entries in the session above).
  The one 292-step turn never compacted because its per-step context (~137k)
  stayed under the window.
- **Codex dollar figures** (02, 04: "$327 Astra", "$873", "~$100 for one
  turn"). `usage-routes.ts` `costCodex` bills cached input at the full $2.50/M
  input rate, and ~97% of that input was cached. Cached input is billed at a
  discount, so every Codex $ figure, including the UsagePanel's, is overstated
  several-fold. Token counts are fine; the dollar amounts are not. The Claude
  rates (3/15/0.30/3.75) were applied to Opus/Fable without checking the
  per-model price.
- **"Refresh storm would show as write volume"** — the real refresh storm
  (bug 1) went unnoticed because it shows up as *read* growth.
