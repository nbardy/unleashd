## What changed
- `ingest/conversation-list.ts` serves `page()` = the settled prefixes of the bound sessions (`Ingest.messages`) merged with the runtime's overlay by `mergeSessionMessages`.
  - While a turn runs, changes are queued. They settle when the process exits (the setter on `runtime.process`).
  - Row counts are the length of the served history, so overlapping sessions count once.
  - A replaced history bumps the epoch and sends a new `{t:'rewritten'}` row patch; the client refetches.
- `ingest/runtimes.ts`: runtimes are built from records. App-created records are built at boot; any other conversation on first use (GET detail/messages, WS command).
- Runtime `messages` holds only the overlay. Label, activity and count come from one history port.
- The runtime's label rule now folds lines at 60 units, the same as the crate.
- Records created after boot join through `findBySession`. A session no record binds is discovered, as the old poller did.
- External "running elsewhere" status uses one backstop timer that is armed only while something is active.
- `/api/search` uses `Ingest.search`.
