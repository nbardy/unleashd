# Budget pass: Buddies layer (branch refactor/budget-buddies, db98212..5080810, 14 commits)
server/src/buddies went from 4,875 to 4,429 lines (-446). Without turn-policy.ts it went from 4,172 to 3,819; the design budget is ~1.9k.
Per module, before -> after (budget): channels 744->721 (500, which also has to cover slots 114->103, gate 208->141 and media 139), mcp 691->608 (400), turn-policy 703->610 (n/a), routes 697->493 (250), memory-review 503->436 (220), runner 424->420 (350), core 170->253 (n/a; it now holds the shared schemas), grants 130->120 (100), briefing 147->157 (150), events 27->38 (30), policy-port 101, builder 13. schedule.ts (16) and provider-capability.ts (16) were folded into their callers. cursor-ephemeral.ts (32) became detached-cli.ts (76).
What was consolidated:
- DEADCODE: deleted buildFirstTurnCliContent and extractBuddyMemorySnapshot. Their 3 tests are now 1 runtime test that checks the prompt the provider actually receives: builder/buddy/chat markers, the briefing sent once, the generation marker, no swarm prefix.
- Routes and tools: one definition in core.ts each for the task changes, the schedule fields, the buddy create/update fields (including the manager and profile Setting mapping), the key and the evidence. Also shared: taskDetail, and announcePost, which replaced 5 copies of "open channel, emit posted".
- One runDetached replaces the reply gate's and the memory reviewer's two hand-rolled CLI loops. It also does the Cursor transcript erase.
- Table-driven: the HTTP status per crate error code, doc scopes, the gate harnesses (an exhaustive Record<Provider, flags|null>), and the owner routes (keyed 'METHOD STATUS path'; same 38 routes, same order, same statuses, checked by script).
- One scanGenerations for seats and DMs (it replaces liveGenerations). One onTurnDrained for chat runs and runner turns. One readBuddyState for the briefing and the reviewer. One grant issuer (revoke(bearer) is deleted). One fresh-turn job builder. One seat-prompt composer (the prompt text is unchanged).
- Addon: dropped pruneEvents, listChannels and getConversation, which had no TS caller, along with their store fns. The event idempotency assertion is kept. index.d.ts was regenerated by the napi build (-3 lines), and the crate README was updated.
Checks on the clean committed tree: `pnpm test` (all suites: server 194/195 with 1 pre-existing todo, 0 failures), check-client-invariants (8/8), and the crate tests (25 + 1 + node 2). One server test failed once and I could not reproduce it in 4 reruns, so treat it as flaky; I did not identify which test it was.
Still over budget, and why:
- policy-port.ts, builder.ts, buddy-conversation-slots.ts and channel-reply-gate.ts cannot be folded without editing their importers: server.ts, http/conversation-routes.ts and conversations/*, which are outside this lane. policy-port is a pure pass-through, so fold it into the runner once server.ts can change (about -60).
- BuddyBuilderTurnPolicy repeats ChatTurnPolicy's no-ops, but it cannot extend it: ChatTurnPolicy declares preflight()/startTurn() with no parameters. The fix belongs in turns/policy.ts, which the server-core lane owns (about -40).
- channels, mcp and memory-review now mostly hold behavior: thread seats and generations, the follow-up gate and chain limit, retry-on-another-harness, media canonicalization, 14 tool schemas with their descriptions, and the 4-rung reviewer ladder with per-harness sandbox flags. The §8 budget assumed the 12-tool / 35-route model with features merged; reaching ~1.9k means cutting features, not consolidating.
- Behavior notes: MCP keys and evidence now use the routes' stricter bounds (key <=200 chars trimmed; evidence items non-empty and <=4000). A missing doc scopeId returns 400 instead of 500. The gate's SIGKILL now fires 5 s after a stop instead of at timeout+5 s.
