not a current Wave_sim work ledger or instruction to restart its production team.
The owner requested simulation, design reconsideration, a second coding pass and
a response to the CEO's original report.

## Intended business workflow

CEO owns priorities, dependency decisions, review and owner communication.
Project Lead coordinates Product, GTM, Wave Simulation and Frontier Research.
Product owns Engineer and Designer; GTM owns Market Research. Existing identities,
reporting lines, projects and artifacts should survive a failed provider turn.

The product program starts with **M0: trustworthy controls**: freeze selected
source, check actual fixtures, fix units/ranges/counts and invalid inputs, and
verify real geometry effects in the browser. It explicitly asks for implementation,
not another broad audit. The next demonstration is authored foil/body and pool
assets that edit, measure, undo, reopen and export with independent shape checks.

Market evidence should improve Designer's real customer workflow; acceptance
fixtures should reach Engineer; verification should reach Simulation. Frontier
findings need explicit assumptions, full cost and a falsifier before engineering
qualification. A useful negative review is a deliverable, not a reason to invent
a physics success. CAD rendering, static numerical proof and authored-pool dynamic
simulation are different milestones. Design MVP does not require the dynamic GPU
campaign; the combined MVP does.

Only actual dependencies should serialize work. One GPU runner is an operating
constraint, not a claim that Buddies provides a host lease. Research and unsent
outreach drafting can progress independently. Reviewed demo videos and an exact
usable account precede any separately authorized customer outreach.

## What a useful management session must decide

1. Is there already an open assignment on this project?
2. Was this specific input admitted, or is it queued/held?
3. Does a failed attempt have a saved, versioned checkpoint?
4. Did a reply persist, and did a separate return input execute?
5. Has the intended consumer reviewed that artifact/version?
6. Who can recover it, and what remains of the original limits?
7. Which exact project criteria can close from this evidence?

Current projects answer responsibility and completion. Runs answer attempt state.
Messages answer communication. Checkpoints attest saved artifacts and effects.
Consumer review is an explicit request/reply with versioned evidence; provider
completion is not consumer acceptance. Memory is orientation and historical
evidence, not a competing project ledger.
